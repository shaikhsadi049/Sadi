I have resolved the issue for NGI FC_MF_CIFINQ (ITRD MF_CIFINQ_Passport v1.0). Please find the resolution details and deployment prerequisites below:

Category Details
Issue passportNo and passportExpiryDate returned by the service, consumed by DBank PRO for SID opening, were invalid. BDI requested the data source for these fields to be changed.
Analysis Root cause in the DB function ap_ngi_ext_mf_cif_inq. The cursor sourced passportNo from ci_custdetl.REF_CUST_PSPT and passportExpiryDate from ci_custdetl.DAT_PSPT_EXPIRY, which the bank does not maintain. It also returned no icType column at all, so the Java layer was mapping icType from flg_replicate, a replication flag unrelated to identity type.
Fix Details Re-sourced the three fields in the function per the ITRD, in all six var_pi_id_type branches (99, 00, 30, 50, 90, 91):
  • icType – new cursor column, from UDF TXT_696
  • passportNo – from CI_CUSTMAST.COD_CUST_NATL_ID, only when icType = 'PAS'
  • passportExpiryDate – from UDF TXT_762, only when icType = 'PAS', normalised to YYYYMMDD
For any other icType both passport fields return NULL. Java change is a single line in MFCIFInqResWrapper, reading icType from the new cursor column. No new DB object; the other response fields are untouched.
Testing Done Verified in UAT via Postman. CIF 1786984 (KTP) now returns icType = "KTP" with both passport fields NULL, as per the ITRD. Previously icType returned the replication flag "N".
Deployment Prerequisite Crucial: the function must be deployed before the JAR, as the JAR reads the new icType cursor column. The UDF reads are scoped to COD_TASK = 'CIM09'; please confirm TXT_696 and TXT_762 are captured under the same task in the target environment.
Artifact Location DB script and updated JAR: D:\OpenShift\FCRNGIMFCifInq\<date>\
The pre-change function is kept as ap_ngi_ext_mf_cif_inq_OLD.sql for rollback, to be rolled back together with the backup JAR.
Next Step Deployment to the UAT Linux environment, followed by end-to-end testing with DBank PRO.
Impacted Units Service: FCRNGIMFCifInq
DB Function: ap_ngi_ext_mf_cif_inq
Java Class: MFCIFInqResWrapper
Open Point The only PAS customer in UAT is CIF 14508534, whose COD_CUST_NATL_ID holds a sixteen digit value (NIK shape) where the ITRD sample is AB1234567Z. The mapping follows the ITRD exactly, but has not been exercised against a realistic passport number. Request BDI to confirm against production before SIT sign off.
